# AI-Based Detection of Cyber Threats in Unidirectional IP Traffic

A mini project that trains classical machine learning models to detect cyber threats from network flow data, and tests how well detection holds up when only **one direction** of traffic is visible.

## Background

Most intrusion detection research assumes a monitor can see both the request and the response of every connection. Some high-security networks (industrial control systems, SCADA, critical infrastructure) deliberately break that assumption with a **unidirectional gateway (data diode)**, which physically allows traffic to flow in only one direction. A monitor on such a link never sees the return path.

This project asks: **can machine learning still detect threats accurately using only forward-direction traffic features?**

## Approach

Every flow is split into two feature sets:

- **Unidirectional**: forward-direction (source to destination) features only, such as packet counts, packet lengths, inter-arrival times, header lengths and flag counts (22 features)
- **Full (bidirectional)**: the unidirectional features plus the backward-direction (return path) statistics

The same three models are trained and evaluated on both sets, so the only variable is what the monitor can see.

| Model | Implementation |
|---|---|
| Random Forest | scikit-learn `RandomForestClassifier` |
| SVM | scikit-learn `SVC` (RBF kernel) |
| Gradient Boosting | scikit-learn `HistGradientBoostingClassifier` (stand-in for XGBoost) |

## Dataset

The project uses a sample dataset that follows the **CICIDS2017** flow schema (the same Fwd/Bwd columns that CICFlowMeter produces). It is generated by `data/generate_synthetic_traffic.py` and contains about 19,000 flows across seven classes:

`BENIGN`, `DoS`, `PortScan`, `BruteForce`, `Botnet`, `WebAttack`, `Infiltration`

The classes are imbalanced on purpose, as in real traffic, and the models use class-balanced weighting where supported.

To use real CICIDS2017 data instead, place its CSV files in `data/raw/`. `preprocess.py` detects them automatically and uses them in place of the sample data. No code changes are needed.

## Getting Started

```bash
pip install -r requirements.txt
python data/generate_synthetic_traffic.py    # skip if using real CICIDS2017 CSVs
cd src
python train_model.py                        # trains all 3 models on both feature sets
python evaluate.py                           # generates the plots in outputs/
```

Training takes a few seconds per model on the sample dataset.

## Results

Results from a run on the sample dataset:

| Feature Set | Model | Accuracy | F1-Score |
|---|---|---|---|
| Unidirectional | Random Forest | 0.9842 | 0.9841 |
| Unidirectional | SVM | 0.9765 | 0.9781 |
| Unidirectional | Gradient Boosting | 0.9844 | 0.9845 |
| Full (bidirectional) | Random Forest | 0.9894 | 0.9893 |
| Full (bidirectional) | SVM | 0.9830 | 0.9838 |
| Full (bidirectional) | Gradient Boosting | 0.9894 | 0.9893 |

**Takeaway:** removing the return-path features costs only about 0.5 to 1 percentage point of accuracy. Gradient Boosting and Random Forest perform best, and SVM trails slightly. These numbers come from the sample dataset, so expect them to change on real CICIDS2017 data.

## Outputs

Running the pipeline writes these files to `outputs/`:

- `metrics_summary.json`: accuracy, precision, recall, F1 and training time for every model and feature set
- `best_model_report.txt`: per-class classification report for the best unidirectional model
- `confusion_matrix.png`: confusion matrix of the best unidirectional model
- `model_comparison.png`: unidirectional vs full comparison across models
- `feature_importance.png`: top 15 unidirectional features (Random Forest)
- `models/`: trained models saved with joblib

## Using Real XGBoost

The code uses scikit-learn's gradient boosting by default. To switch to real XGBoost:

```bash
pip install xgboost
```

Then set `USE_XGBOOST = True` at the top of `src/train_model.py`. The rest of the pipeline works unchanged.
